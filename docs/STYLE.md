# Writing style

## Who reads this

Data engineers who install and configure Fita, and data stewards who review records every day. Write for someone smart who has never seen an MDM before.

## Rules

- One page, one job. A guide answers one "how do I" question.
- Start with what the reader gets, then the steps.
- Short sentences. Active voice. Second person ("you").
- Every command and config block must run as written. CI runs the code blocks marked `run`.
- Show real looking but invented data. Never real companies, people or tax ids.
- Use the same names as the product. Golden record, source record, domain, attribute, rule, review queue.
- Link the first mention of a concept to its page in `concepts/`.
- No marketing language, no superlatives, no pricing.

## Translation

English is the source. A Spanish page keeps the same path under `es/` and the same headings in the same order. Code, config keys and commands are never translated.

## Generated pages

Pages under `reference/` are generated by `scripts/gen-reference.mjs`. Edit the source (doc comments in the Fita repository) instead.
